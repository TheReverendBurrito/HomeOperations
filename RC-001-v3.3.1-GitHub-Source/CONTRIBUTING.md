# Contributing

1. Create a branch from the current default branch.
2. Keep site-specific values in `.env`; never add real credentials or private
   operational data to tests, documentation, fixtures, screenshots, or commits.
3. Use documentation ranges such as `192.0.2.0/24` for sample addresses and
   locally administered MAC addresses for fixtures.
4. Run the validation commands documented in `README.md`.
5. Describe functional, configuration, database-schema, and security effects in
   the pull request.

Contributions must not include third-party assets unless their redistribution
rights are documented.
